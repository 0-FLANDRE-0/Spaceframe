# Spaceframe

우주 전투함을 격자 위에서 직접 설계하고, 그 설계 그대로 실시간 전투에 내보내는
브라우저 게임 겸 시뮬레이터입니다.

설계 단계에서 배치한 함체·장갑·격벽·모듈·배관이 전투에서 그대로 물리적 실체로
작동합니다. 관통 지점에 실제로 무엇이 놓여 있었는지가 피해 결과를 정하고, 전력과
발열이 모듈 동작을 제한하며, 센서 배치와 자함 기동이 적을 얼마나 알 수 있는지를
정합니다.

## 개발 상태

프로토타입입니다. 현재 빌드는 `Spaceframe_v1.31.37.html`의 `<title>`에 표기된
**1.31.37** 입니다.

게임 파일 이름은 `Spaceframe_v<버전>.html` 형식이며 버전이 올라갈 때마다 바뀝니다.
저장소 최상위에는 항상 최신 정식 HTML 하나만 둡니다.

버전별 변경 이력은 [`CHANGELOG.md`](CHANGELOG.md)에 있습니다.
`main`이 최신 통합·안정 브랜치이며, 완성된 작업만 Pull Request를 통해 병합됩니다.

## 실행 방법

빌드 단계가 없습니다. 저장소를 받아 `Spaceframe_v<버전>.html`을 브라우저로 열면
그대로 실행됩니다.

```
git clone https://github.com/0-FLANDRE-0/Spaceframe.git
cd Spaceframe
# Spaceframe_v1.31.37.html 을 브라우저에서 열기
```

파일을 더블클릭하거나 브라우저로 끌어다 놓아도 됩니다(`file://` 로 동작합니다).
설치·의존성·서버·번들러가 필요 없고, 외부 스크립트나 스타일시트를 불러오지 않습니다.
자동 저장과 되돌리기 기반은 브라우저 `localStorage`를 사용합니다. 이름을 붙여 보관하는
설계 슬롯은 IndexedDB에 저장하며, 지원 브라우저에서는 설계 payload를 gzip으로 압축합니다.
IndexedDB를 사용할 수 없는 환경에서는 기존 `localStorage` 방식으로 fallback합니다.

## 프로젝트 구조

단일 HTML 파일 중심입니다.

| 파일 | 내용 |
|---|---|
| `Spaceframe_v<버전>.html` | 게임 전체. HTML·CSS·JavaScript가 한 파일에 들어 있습니다 |
| `CHANGELOG.md` | 버전별 변경 이력 |
| `CLAUDE.md` | 이 저장소에서 작업할 때의 검증·Git 규칙 |

게임 로직은 게임 파일 안의 IIFE 하나에 담겨 있어 바깥에서 직접 호출할 수 없습니다.
대신 페이지에 자체 테스트 하네스가 `window.__SPACEFRAME_*_TEST__` 형태로 노출되어
있습니다(현재 **118개**).

```js
Object.keys(window)
  .filter(k => k.startsWith('__SPACEFRAME') && k.endsWith('TEST__'))
  .map(n => window[n]())
```

각 하네스는 해당 계층의 결정적 단언을 돌려줍니다. 일부 하네스는 반환 구조가 서로 달라
전체 단언 수를 셀 때는 재귀적으로 결과를 훑어야 합니다. 자세한 검증 규칙은 `CLAUDE.md`에
있습니다.

## 구현된 주요 시스템

### 함선 설계

- 격자 기반 함체 작도, 경계 장갑, 내부 격벽
- 모듈 배치 — 반응로, 주엔진, RCS 기동 추력기, 캐패시터, EO/IR/ESM 센서,
  센서 융합 노드, 탄도/미사일 사격통제, 함포, 미사일 발사대, 탄약고, 보호막,
  방열기, 레이더
- 하단 설계 도구를 **기초 / 무장 / 고급** 3개 탭으로 분리. 캐패시터와 FCS처럼 여러
  역할에 걸치는 장비는 필요한 탭에 중복 노출하고, 함포·포탑·미사일 발사대·탄약고는
  무장 탭에 집중
- 터렛 → 마운트 → 무장의 계층형 조립과 탄약 종류별 적재
- 포탑 S규격 레지스트리(S2~S10)와 제품 계보/설치 규격 분리. 현재 `TUR-558D`는
  **S4 3×3m / S5 4.25×4.25m** 두 설치 규격을 지원
- S3 단장·쌍열·3연장, S4 단장·쌍열 마운트와 등급별 호환 무장 구성
- 150mm/60mm/에너지 리피터/고출력 펄스 캐논 및 신규 HPS/VHI 무장의 실제
  본체·약실·포신/가속부 형상, 함체 고정식 설치와 무기별 미세 짐벌
- **HPS S4 220mm Hyper-Output Railgun** — 약 60×700mm, 35kg 장침 관통체를
  6.2km/s로 가속하는 단발 전자기 가속포. S4 마운트 포탑과 함체 고정식 설치 지원
- **VHI HG-132/3** — S7 함체 고정식 132mm 3포신 중량 개틀링. 최고 1,850RPM의
  단계적 스핀업/스핀다운과 별도 132mm Full-Bore AP 탄약 사용
- **4연장 발사대** — 5×1m 고정식 4셀 캐니스터. 호환 미사일과 실제 탑재 수량을 설계
  정보창에서 선택하며 전투 중 재장전은 하지 않는다
- **MFC-1-582A 미사일 사격통제 노드** — 함선 센서 통합 트랙을 ARH 발사해와
  DL/INS 중간유도 패킷으로 변환하며, 탄도 FCS와 역할을 분리
- **범용 광대역 RAM 표면처리** — 장갑층과 별개인 최외곽 surface treatment로 설치하며
  5~20mm 두께, 주파수별 흡수 응답, 질량·가격·국부 손상 상태를 실제 설계에 반영
- 방향성 EO/IR 센서의 단일 boresight/FoV, 15° 단위 지향각 재설정과 실시간 차폐 확인
- 미러모드 대칭 편집 — 대응 모듈의 이동·삭제, 포탑 마운트/무장, 센서 방향,
  탄약고·장갑 전이 설정을 함께 편집
- 전력 수지와 발열 용량 계산, 열배관 작도
- 발전량·연속 소비·버퍼 용량·충방전 처리량·에너지 무장 요구량을 한 화면에서 보는
  설계 Fitting 패널
- 제품 메타데이터와 Cr 가격을 이용한 순수 건조비/전투 준비가 및 구조·장비·무장·탄약
  비용 분해
- 자동 저장·되돌리기(`localStorage`)와 최대 20개 설계 보관함(IndexedDB, gzip 지원)

### 세계관·기업·제품 데이터

- 설계 화면의 `DB`에서 **2592 CE 인류권**의 우주 이동·산업·핵심 연표와 공동 프로젝트를 열람
- Meridian General Industries(MGI), Aegis Dynamic Systems(ADS), Helix Propulsion Systems(HPS),
  Novacore Materials(NCM), Valken Heavy Industries(VHI)의 기업사·거점·문화·강점·관계를 수록
- 다섯 기업의 로고를 단일 HTML 내부 WebP 데이터로 포함해 외부 이미지 파일 없이 표시
- 카탈로그와 설치 모듈 정보의 제작 기업 표기에서 기업 DB로 바로 이동 가능
- MGI 표준 카탈로그에 제품 모델 코드와 `C / M / I / S` 제품 분류 체계를 적용
- 기존 범용 완제품은 MGI 기준제품을 유지하되, 1.31.35부터 **HPS 220mm 레일건 계열**과
  **VHI HG-132/3 계열**처럼 명시적인 기업 고유 제품을 별도 제조사로 등록
- 원재료·라이너는 특정 제조사를 강제로 지정하지 않는다

### 전력과 기동

- 2.4GW 핵융합로와 2.25GJ 내장 버퍼, 가변 면적 캐패시터 뱅크를 하나의 함선 전력 버스로 통합
- 캐패시터는 면적에 따라 저장량·질량·충전/방전 처리량이 선형 증가하며, 에너지 무장은
  남은 방전 처리량을 공유한다. 처리량이 부족하면 충전·연사 주기가 실제로 느려진다
- 주엔진은 전진 가속을 담당하고 약한 짐벌만 제공한다. 후진·횡이동·주 선회는 별도 RCS가
  맡으며, 외벽형 RCS는 실제 노즐 방향과 질량중심까지의 모멘트 암으로 추력과 토크가 결정된다
- 모듈 파괴와 전력 부족은 추진·센서·보호막·무장 성능에 같은 런타임 전력 계약으로 반영된다

### 실시간 전투

- 아군 1척 대 적 함선 교전, 웨이포인트 기반 기동
- 함포 투사체와 별도 객체로 움직이는 **40km급 ARH 미사일**. 1회 부스터,
  4분할 고체 다중펄스 sustain, TVC·자세 RCS·DACS, PN 유도와 능동 레이더 시커를 사용
- 미사일은 MFC가 제공하는 정밀 센서 트랙으로 **DL/INS 중간유도 → ARH handoff**가
  가능하다. 거리 없는 EO/IR 방위만 있으면 MFC가 초기 방위 cue를 주는 MAD를 사용할 수
  있고, MFC가 없거나 파괴되면 센서 정보 없이 발사관 정면 MAD DOG으로 제한된다
- 전술 화면에는 자함이 발사한 미사일의 상태만 표시하며 적 미사일 truth를 직접 노출하지 않는다
- 투사체 비행과 관통, 관통 경로상의 실제 구조물에 따른 내부 손상 전파
- 돌출된 무기 본체·포신/방출부도 독립 충돌체로 판정되어 선체보다 먼저 피격 가능
- 고정식 무장은 FCS 선행사격 해에 맞춰 함체 자세제어를 요청하고, 무기별 미세 짐벌로
  잔여 오차를 보정
- 모듈 파괴가 전력·발열·센서·무장 가용성에 즉시 반영
- 보호막 충전·붕괴·재기동, 열 축적과 과열에 따른 무장 정지
- 축소 시 전술맵 전환

### 관통·폭발·2차 피해

- 운동탄 관통을 고정 `mm RHAe` 수치가 아니라 **penetration family + 실제 관통부 형상 +
  재질 + 질량 + 충돌속도 + 입사각 + 현재 탄자 상태**에서 계산하는 공통 동적 모델로 통합
- Long-rod, Full-bore, Composite-core(HVAP/APCR), Hypervelocity, 미사일
  Penetrating-body 계열이 같은 authoritative 경로를 공유하며, UI의 기준 관통력도 같은
  모델을 표준 조건에서 계산한 값이다
- HVAP/APCR은 외부 캐리어와 실제 고밀도 코어를 분리해 관통 후 코어·부착 캐리어·
  후방 파편·전면 탈락 질량을 각각 처리
- **150mm APHE** 추가 — 저항 임계 신관, 시간지연 폭발, 탄체 전진속도와 방사 파편속도를
  벡터 합성한 후방효과를 사용
- 초고속탄은 관통 깊이와 주변 피해를 분리해, 충돌 과정에서 실제 침적된 운동에너지에
  따라 같은 대표 파편 ray가 더 큰 debris cloud를 대표한다
- 진공 내부 파편은 더 이상 고정 14m에서 사라지지 않으며, 실제 물체와 충돌할 때만
  에너지를 잃고 함체를 빠져나가거나 유효 에너지/속도 이하가 될 때 종료한다

### 범용 전투 AI 코어

- 적함 AI가 특정 함선 설계를 전제로 한 고정 규칙 대신, 현재 함선의 **무장·사거리·화력 방향성·
  탄약·열·전력·기동 성능**을 읽어 자체 전투 능력 모델을 구성
- 적 정보는 실제 적함 객체를 직접 읽지 않고 **센서 트랙**을 통해 World Model에 입력한다
- Planner가 거리와 상대 방위를 후보로 만들고 공격·생존·통제·지속력·정보·위험 점수를 합산해
  `desiredRange`, `desiredAspect`, 접근/이탈 의도를 만든다
- 충분한 TRACK이 있으면 범용 코어의 Flight Intent가 실제 적함 비행제어에 연결되며,
  불충분하거나 유효한 명령을 만들지 못하면 기존 Legacy 전투 기동으로 fallback한다
- 고정식 무장 사용 시 ACQUIRE/SETTLE 자세 우선, 과도한 선회 중 횡이동 억제,
  정지각속도를 고려한 회전 제어와 제한된 Hull-Aim trim을 적용
- 전투 화면의 `AI` 디버그 패널에서 SELF / WORLD / FIRE / PLAN / INTENT / CTRL 상태를
  함선별로 확인할 수 있다

### 센서와 표적 정보

- EO / IR / ESM / RADAR 네 계열 센서, 각각의 커버리지 프로파일과 탐지 한계
- 함선 신호 특성(RCS·열·EM 방출)을 설계 형상에서 산출
- RCS는 함체 형상·외부 장갑 재질·모서리·노출 모듈을 합성한다. **3.0GHz는
  1.31.36까지의 방향별 RCS와 정확히 같은 기준점**이고, 실제 레이더 주파수에서는
  diffuse/specular/edge/module 성분별 연속 주파수 응답을 적용한다
- 설계 RCS 오버레이에서 0.1~300GHz 분석 범위의 주파수 슬라이더와 S/X/Ku/Ka/W
  대역 바로가기를 사용해 방향별 RCS 곡선을 비교할 수 있다. 밴드 이름은 UI 분류일 뿐
  물리 계산은 실제 Hz를 사용하며, 검증 범위 밖 요청도 endpoint clamp 방식으로 계산된다
- 외장 RAM의 주파수별 흡수와 손상 상태가 해당 방향의 실제 RCS에 반영되고, 광학 대비
  저감은 geometric CS와 분리된 EO 신호 계수로 취급된다
- 센서 융합 트랙 — 방위·거리·속도·가속도를 관측 이력에서 추정하고 각각의
  불확실성을 분리해 관리
- EM 방출 대역별 분류, ESM 수동 위치추정 — 송신출력 prior 기반 신호세기 거리추정,
  함내 다중 ESM 기선의 방위 정밀도, 관측 이력 기반 TMA의 세 증거를 융합
- 능동 레이더 — **2면 독립 회전식 PESA**, 2.6~3.4GHz S-band(기준 3.0GHz).
  두 면이 공통 회전 마스트를 공유하면서 각자 SEARCH/TWS 빔을 스케줄링하고,
  STT에서는 마스트가 표적 중심 섹터를 지향한 채 한 면이 정밀 추적을 유지하고
  반대 면은 가능한 영역의 탐색을 계속한다
- 레이더 탐지는 RF 송신출력·안테나 이득·주파수·표적 RCS·왕복 R⁴ 손실·수신기 잡음에서
  계산한 SNR과 Pd를 사용한다. SEARCH/TWS/STT는 서로 다른 dwell과 RF duty를 사용한다
- 거리를 확정하지 못한 접촉은 방위 쐐기 또는 불확실성 타원으로만 표시
- 레이더 TWS/STT의 거리·도플러·측정 이력이 Sensor Fusion과 FCS까지 이어진다
- EO 식별은 점접촉 → 크기/방향 → 함체 윤곽 → 외부 모듈 → **Stage 5 BDA LOCK**으로
  단계화되어 있으며, LRF가 4km 이내를 확정하면 근거리 BDA 문턱을 완화한다
- BDA는 관측된 외부 모듈 상태와 최근 피격 흔적의 **센서 기반 스냅샷**만 사용하며,
  적 함선의 실제 내부 HP를 직접 읽지 않는다
- 1.21 계열의 표적 전술도 레이아웃을 현재 센서 계약으로 복원한 락온 인디케이터에서
  표적 방향·거리·관측 구조 상태·보호막·BDA 모듈/최근 피격 정보를 표시한다
- BDA 상세 모듈과 피격점은 **락온 표적 인디케이터에만** 표시하고 전장 본화면에는 노출하지 않는다
- 사격통제 해는 센서 트랙의 방위·거리·속도·가속도 불확실성을 실제 탄착 예측 오차로
  전파하며, 거리가 확정되지 않은 수동 접촉의 자동사격은 계속 차단한다
